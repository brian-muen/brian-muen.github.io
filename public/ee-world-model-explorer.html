The current collector derives action_continuous from consecutive measured TCP poses, so it records achieved motion rather than the raw command sent to the controller. A residual is meaningful only after command and realized motion share units and coordinate frames. With only the current field the residual r = Δxactual − Δacmd collapses to zero. The selected proposal does not require a residual target, but honest command-execution analysis and the residual ablations do, so both streams should still be stored.

Appendix · conceptual pre-DiT command-response adapter An earlier page alternative, kept as proposed ablation D not selected

A separately trained adapter predicts the realized EE trajectory before visual generation, and the DiT conditions on that prediction. It is a clean engineering cascade, but it factorizes the same timestep as p(o | x̂) p(x̂ | …) when observation and state are two views of one physical configuration.

Δx̂actual = Fadapter(xt, Δacmd) → x̂t+1 = xt ⊕ Δx̂actual Learn one; derive the other.

Worth running as ablation D: it tests whether a separately trained physical predictor helps vision. WEAVER maps action and current robot state into a future state trajectory and reports lower generation quality when conditioning directly on joint velocities. The selected proposal instead asks one DiT to own p(o, x | …).

Terminology: τ is flow-matching noise time and z is a VAE latent, while x is the measured EE state. In the selected proposal both future latents and future EE state are denoised on an aligned schedule; the previously committed state conditions the next frame.
